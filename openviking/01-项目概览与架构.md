## 1. 项目简介

### 1.1 什么是 OpenViking？

**OpenViking** 是由**字节跳动火山引擎 Viking 团队**开源的、专为 **AI Agent** 设计的**上下文数据库**。

它将传统 RAG 的扁平存储模式转变为**文件系统范式**，让开发者可以像管理本地文件一样构建 Agent 的大脑。

### 1.2 为什么需要 OpenViking？

在构建 AI Agent 时，开发者面临五大挑战：

| 挑战 | 传统方案 | OpenViking 方案 |
|------|----------|-----------------|
| **上下文碎片化** | 记忆在代码、资源在向量库、技能散落各处 | 统一文件系统结构化管理 |
| **上下文猛增** | 简单截断导致信息损失 | 分层加载 (L0/L1/L2) 按需获取 |
| **检索效果差** | 平铺式向量检索，缺乏全局视野 | 目录递归检索，理解完整语境 |
| **不可观测** | 检索链路黑箱，难以调试 | 可视化检索轨迹 |
| **记忆迭代有限** | 仅有用户记忆 | 自动提取 Agent 经验记忆 |

### 1.3 核心理念


## 2. 核心概念

### 2.1 Viking URI

OpenViking 使用统一的资源标识符 `viking://` 协议：

```
viking://
├── resources/           # 资源：项目文档、代码库、网页
│   ├── my_project/
│   │   ├── docs/
│   │   └── src/
│   └── ...
├── user/                # 用户：个人偏好、习惯
│   └── memories/
│       ├── preferences/
│       └── ...
└── agent/               # Agent：技能、指令、任务记忆
    ├── skills/
    └── memories/
```

### 2.2 三大上下文类型

| 类型 | 用途 | 示例 |
|------|------|------|
| **Resource** | 外部知识 | API 文档、代码仓库 |
| **Memory** | Agent 认知 | 用户偏好、经验积累 |
| **Skill** | 可调用能力 | 搜索技能、分析技能 |

### 2.3 三层信息模型

| 层级 | Token 限制 | 用途 |
|------|-----------|------|
| **L0** | ~100 | 向量搜索、快速过滤 |
| **L1** | ~2k | Rerank 精排、内容导航 |
| **L2** | 无限制 | 完整内容、按需加载 |

## 7. 检索机制

### 7.1 两阶段检索流程

```mermaid
flowchart TB
    Q[查询] --> IA[IntentAnalyzer]
    
    subgraph Intent["意图分析"]
        IA --> TQ1[TypedQuery 1]
        IA --> TQ2[TypedQuery 2]
        IA --> TQ3[TypedQuery N]
    end
    
    TQ1 --> HR1[层级检索]
    TQ2 --> HR2[层级检索]
    TQ3 --> HR3[层级检索]
    
    subgraph Hierarchical["层级检索"]
        HR1 --> GS[全局搜索定位]
        GS --> R1[递归探索]
        R1 --> R2[分数传播]
    end
    
    R2 --> Merge[结果合并]
    Merge --> RR[Rerank 精排]
    RR --> Result[最终结果]
```

### 7.2 意图分析

```mermaid
flowchart LR
    Input[用户查询] --> LLM[LLM 分析]
    
    subgraph Analysis["分析输出"]
        LLM --> Type[context_type<br/>MEMORY/RESOURCE/SKILL]
        LLM --> Intent[intent 查询目的]
        LLM --> Priority[priority 优先级]
        LLM --> Query[重写查询]
    end
    
    Type --> Output[TypedQuery]
    Intent --> Output
    Priority --> Output
    Query --> Output
```

### 7.3 递归检索算法

```mermaid
flowchart TB
    Start[开始] --> Init[初始化优先队列]
    Init --> Global[全局向量搜索]
    Global --> Push[加入优先队列]
    
    Loop{队列非空?}
    Push --> Loop
    
    Loop -->|Yes| Pop[弹出最高分目录]
    Pop --> Search[搜索子节点]
    Search --> Score[计算最终分数]
    
    Score --> Threshold{分数>阈值?}
    Threshold -->|No| Skip[跳过]
    Threshold -->|Yes| Collect[加入结果集]
    
    Collect --> Leaf{是叶子节点?}
    Leaf -->|Yes| Back[继续循环]
    Leaf -->|No| PushDir[目录加入队列]
    PushDir --> Back
    
    Loop -->|No| Check[收敛检测]
    Check --> Done{top-k稳定?}
    Done -->|Yes| Return[返回结果]
    Done -->|No| Back
```

## 9. 快速开始

### 9.1 安装

```bash
pip install openviking
```

### 9.2 配置

创建 `~/.openviking/ov.conf`:

```json
{
  "embedding": {
    "dense": {
      "api_base": "https://ark.cn-beijing.volces.com/api/v3",
      "api_key": "your-api-key",
      "provider": "volcengine",
      "dimension": 1024,
      "model": "doubao-embedding-vision-250615"
    }
  },
  "vlm": {
    "api_base": "https://ark.cn-beijing.volces.com/api/v3",
    "api_key": "your-api-key",
    "provider": "volcengine",
    "model": "doubao-seed-1-8-251228"
  }
}
```

### 9.3 基本使用

```python
import openviking as ov

# 初始化
client = ov.OpenViking(path="./data")
client.initialize()

# 添加资源
result = client.add_resource("https://docs.example.com")
uri = result['root_uri']

# 层级浏览
ls = client.ls(uri)
abstract = client.abstract(uri)
overview = client.overview(uri)

# 语义搜索
results = client.find("认证方法", target_uri=uri)

# 会话管理
session = client.session()
session.add_message("user", [ov.TextPart("我喜欢...")])
session.commit()

# 关闭
client.close()
```

## 12. 最佳实践

### 12.1 上下文加载策略

```mermaid
flowchart TB
    Query[用户查询] --> L0[L0 向量搜索]
    L0 --> Candidates[候选集]
    Candidates --> Score[评分排序]
    Score --> TopK{top-k结果}
    
    TopK --> Check{需要详情?}
    Check -->|Yes| L1[加载 L1]
    Check -->|No| ReturnL0[返回 L0]
    
    L1 --> NeedMore{还需要更多?}
    NeedMore -->|Yes| L2[加载 L2]
    NeedMore -->|No| ReturnL1[返回 L1]
    L2 --> ReturnL2[返回 L2]
```
