## 2. 核心流程

### 2.1 资源添加流程

```mermaid
sequenceDiagram
    participant C as Client
    participant S as Service
    participant P as Parse
    participant VFS as VikingFS
    participant Q as SemanticQueue
    participant VB as VectorDB
    participant M as Model

    C->>S: add_resource(path)
    S->>P: parse(path)
    P->>VFS: create_tree()
    VFS->>Q: enqueue()
    
    Q->>M: generate L0 (async)
    M-->>Q: L0 content
    Q->>VFS: write .abstract.md
    
    Q->>M: generate L1 (async)
    M-->>Q: L1 content
    Q->>VFS: write .overview.md
    
    Q->>VB: index(uri, vector)
    VB-->>Q: confirmed
    
    S-->>C: result {root_uri}
```

### 2.2 检索流程

```mermaid
sequenceDiagram
    participant C as Client
    participant S as SearchService
    participant IA as IntentAnalyzer
    participant HR as HierarchicalRetriever
    participant R as Rerank
    participant VB as VectorDB
    participant VFS as VikingFS
    participant M as Model

    C->>S: find(query, target_uri)
    
    alt search mode
        S->>IA: analyze(query, session)
        IA->>M: LLM intent analysis
        M-->>IA: TypedQuery[]
        IA-->>S: queries
    else find mode
        S->>S: use raw query
    end
    
    S->>HR: retrieve(queries)
    
    loop 层级检索
        HR->>VB: global search
        VB-->>HR: candidate dirs
        HR->>HR: push to priority queue
        
        loop 递归探索
            HR->>HR: pop high score dir
            HR->>VB: search children
            VB-->>HR: child results
            HR->>HR: calculate final score
            HR->>HR: push sub-dirs to queue
        end
    end
    
    HR-->>S: candidates
    
    alt need rerank
        S->>R: rerank(query, candidates)
        R->>M: LLM scoring
        M-->>R: scores
        R-->>S: sorted results
    end
    
    S->>VFS: load L0/L1
    S-->>C: FindResult
```

### 2.3 会话提交流程

OpenViking 的 `session.commit()` 分两阶段：**Phase 1 同步归档（PathLock 保护）**，**Phase 2 异步提取记忆**。

```mermaid
sequenceDiagram
    participant C as Client
    participant SeS as SessionService
    participant Msg as Message
    participant Comp as Compressor
    participant ME as MemoryExtractor
    participant VFS as VikingFS
    participant VB as VectorDB
    participant M as Model

    Note over C,SeS: Phase 1：同步归档
    C->>SeS: session.commit()
    SeS->>Msg: get messages
    SeS->>Comp: compress(index)
    Comp->>VFS: archive messages
    Comp->>M: generate summary (L0/L1)
    M-->>Comp: summary
    Comp->>VFS: write .abstract/.overview
    SeS-->>C: {status: "accepted",<br/>task_id, archive_uri}

    Note over SeS,VB: Phase 2：异步提取（task_id 跟踪）
    SeS->>ME: extract(messages)
    ME->>M: LLM 分类 + 摘要
    M-->>ME: 8 类候选记忆

    loop 每个候选记忆
        ME->>VB: 向量预筛
        VB-->>ME: 相似记忆 Top-K
        ME->>M: LLM 决策 CREATE / UPDATE / MERGE / SKIP
        alt CREATE / UPDATE / MERGE
            ME->>VFS: 写入 memories/...
            ME->>VB: 更新向量
        else SKIP / patterns/cases (不更新)
            ME->>ME: 仅记录决策
        end
    end
```

### 3.2 数据模型关系

OpenViking 共有 **3 种上下文类型 + 8 种记忆分类**，关系如下：

```mermaid
erDiagram
    Resource ||--o{ L0 : has
    Resource ||--o{ L1 : has
    Resource ||--o{ L2 : has
    Resource ||--o{ Relation : relates

    Session ||--o{ Message : contains
    Session ||--o{ Archive : archives

    Message ||--o{ Part : has
    Part ||--o| TextPart : kind
    Part ||--o| ContextPart : kind
    Part ||--o| ToolPart : kind

    Memory ||--o{ Profile : "user/profile.md"
    Memory ||--o{ Preference : "user/preferences/"
    Memory ||--o{ Entity : "user/entities/"
    Memory ||--o{ Event : "user/events/"
    Memory ||--o{ Case : "agent/cases/"
    Memory ||--o{ Pattern : "agent/patterns/"
    Memory ||--o{ Tool : "agent/tools/"
    Memory ||--o{ SkillMem : "agent/skills/"

    Skill ||--o{ Script : has

    L0 }|--|| Vector : indexed_by
    L1 }|--|| Vector : indexed_by
    L2 }|--|| Vector : indexed_by
```

> 8 类记忆分别对应 `MemoryCategory` 中的 PROFILE、PREFERENCES、ENTITIES、EVENTS、CASES、PATTERNS、TOOLS、SKILLS（详见 `openviking/session/memory_extractor.py`）。其中 `profile` 是单文件，`patterns/cases/events` 不可更新。

## 4. 数据流向

### 4.1 写入数据流

```mermaid
flowchart LR
    subgraph Input["输入"]
        PDF[PDF]
        MD[Markdown]
        URL[URL]
        Git[GitHub]
    end

    subgraph Parse["解析"]
        PDF --> P1[PDF Parser]
        MD --> P2[Markdown Parser]
        URL --> P3[URL Parser]
        Git --> P4[Git Parser]
    end

    subgraph Build["树构建"]
        P1 --> TB[TreeBuilder]
        P2 --> TB
        P3 --> TB
        P4 --> TB
    end

    subgraph Store["存储"]
        TB --> AGFS[AGFS]
        AGFS --> Queue[SemanticQueue]
    end

    subgraph Index["索引"]
        Queue --> SP[SemanticProcessor]
        SP --> L0[L0 生成]
        SP --> L1[L1 生成]
        L0 --> VB[VectorDB]
        L1 --> VB
    end
```

### 4.2 读取数据流

```mermaid
flowchart LR
    Query[查询] --> Intent[意图分析]
    
    Intent --> Typed[TypedQuery]
    
    Typed --> Global[全局搜索]
    
    Global --> TopK[Top-K 目录]
    
    TopK --> Queue[优先队列]
    
    Queue --> Loop{递归}
    
    Loop --> Pop[弹出]
    Pop --> Search[搜索子节点]
    Search --> Score[计算分数]
    
    Score --> Filter[阈值过滤]
    Filter --> Collect[收集结果]
    Filter --> Push[子目录入队]
    
    Push --> Loop
    
    Loop --> Done{队列空?}
    Done --> Rerank[Rerank]
    
    Rerank --> Load[加载 L0/L1]
    Load --> Return[返回结果]
```

## 5. 状态机

### 5.1 资源处理状态

```mermaid
stateDiagram-v2
    [*] --> Pending: add_resource()
    Pending --> Processing: 开始解析
    Processing --> Indexed: 索引完成
    Indexed --> Ready: L0/L1 生成完成
    Ready --> [*]
    
    Processing --> Failed: 解析失败
    Failed --> [*]
```

### 5.2 会话状态

```mermaid
stateDiagram-v2
    [*] --> Created: client.session()
    Created --> Active: add_message() / used()
    Active --> Active: add_message() / used()
    Active --> Archiving: commit() Phase 1
    Archiving --> Active: archive_uri 返回
    Archiving --> Extracting: Phase 2 异步
    Extracting --> Active: task_id 完成 (后台)
    Active --> [*]: client.delete_session()
```

> Phase 2 通过 `client.get_task(task_id)` 跟踪状态。

### 5.3 记忆更新状态

```mermaid
stateDiagram-v2
    [*] --> Extracted: 从消息提取
    Extracted --> Classifying: 分类到 8 类<br/>(profile/preferences/<br/>entities/events/<br/>cases/patterns/<br/>tools/skills)

    Classifying --> Filtering: 向量预过滤
    Filtering --> Deduplicating: LLM 去重决策

    Deduplicating --> Decision
    Decision --> Creating: CREATE
    Decision --> Updating: UPDATE<br/>(可合并: profile/<br/>preferences/entities/<br/>tools/skills)
    Decision --> Skipping: SKIP<br/>(不可更新: cases/<br/>patterns/events)

    Creating --> Stored: 写入 .abstract/.overview/原文 + 向量
    Updating --> Stored

    Stored --> [*]
    Skipping --> [*]
```

> 不可更新的 `cases / patterns / events` 在重复时不会覆盖，只会创建新记录或跳过。
