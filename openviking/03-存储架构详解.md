## 1. 架构概述

### 1.1 双层存储设计

```mermaid
flowchart TB
    subgraph Application["应用层"]
        Client[OpenViking Client]
    end

    subgraph VikingFS["VikingFS 抽象层"]
        URI[URI 映射]
        Access[层级访问]
        Relation[关联管理]
    end

    subgraph Storage["存储层"]
        subgraph Content["内容存储 AGFS"]
            L0[L0 摘要]
            L1[L1 概览]
            L2[L2 详情]
            Media[多媒体]
        end

        subgraph Index["索引存储 向量库"]
            URI_Idx[URI 索引]
            Vector[向量索引]
            Meta[元数据]
        end
    end

    Client --> VikingFS
    VikingFS --> Content
    VikingFS --> Index
```

### 1.2 存储层对比

| 存储层 | 职责 | 存储内容 |
|--------|------|----------|
| **AGFS** | 内容存储 | L0/L1/L2 完整内容、多媒体文件、关联关系 |
| **向量库** | 索引存储 | URI、向量、元数据（不存储文件内容） |

### 1.3 设计优势

1. **职责清晰** - 向量库只负责检索，AGFS 负责存储
2. **内存优化** - 向量库不存储文件内容，节省内存
3. **单一数据源** - 所有内容从 AGFS 读取，向量库只存引用
4. **独立扩展** - 向量库和 AGFS 可分别扩展

## 2. VikingFS 虚拟文件系统

### 2.1 URI 抽象

VikingFS 是统一的 URI 抽象层，屏蔽底层存储细节：

```mermaid
flowchart LR
    subgraph URI["Viking URI"]
        V1["viking://resources/docs/auth"]
        V2["viking://user/memories"]
        V3["viking://agent/skills/search"]
    end

    subgraph Mapping["映射"]
        M1["→ /local/resources/docs/auth"]
        M2["→ /local/user/memories"]
        M3["→ /local/agent/skills/search"]
    end

    V1 --> M1
    V2 --> M2
    V3 --> M3
```

### 2.2 核心 API

| 方法 | 说明 |
|------|------|
| `read(uri)` | 读取文件内容 |
| `write(uri, data)` | 写入文件 |
| `mkdir(uri)` | 创建目录 |
| `rm(uri)` | 删除文件/目录 |
| `mv(old, new)` | 移动/重命名 |
| `abstract(uri)` | 读取 L0 摘要 |
| `overview(uri)` | 读取 L1 概览 |
| `relations(uri)` | 获取关联列表 |
| `find(query, uri)` | 语义搜索 |

### 2.3 URI 协议

```
viking://{context_type}/{path}

# 示例
viking://resources/project/docs/api.md
viking://user/memories/preferences/ui.md
viking://agent/skills/code-search/script.py
```

## 3. AGFS 内容存储

### 3.1 后端类型

| 后端 | 说明 | 配置项 |
|------|------|--------|
| `localfs` | 本地文件系统 | `path` |
| `s3fs` | S3 兼容存储 | `bucket`, `endpoint` |
| `memory` | 内存存储（测试用） | - |

### 3.2 目录结构

每个上下文目录遵循统一结构：

```mermaid
graph TD
    Root["viking://resources/docs/auth/"]
    Root --> Abstract[".abstract.md<br/>L0: 摘要"]
    Root --> Overview[".overview.md<br/>L1: 概览"]
    Root --> Relations[".relations.json<br/>关联数据"]
    Root --> OAuth["oauth.md<br/>L2: 详情"]
    Root --> JWT["jwt.md<br/>L2: 详情"]
    Root --> API["api-keys.md<br/>L2: 详情"]
```

### 3.3 文件说明

| 文件 | 内容 |
|------|------|
| `.abstract.md` | L0 摘要 (~100 tokens) |
| `.overview.md` | L1 概览 (~2k tokens) |
| `*.md` | L2 完整内容 |
| `.relations.json` | 关联资源列表 |

## 4. 向量库索引

### 4.1 Collection Schema

```mermaid
classDiagram
    class ContextDoc {
        +string id
        +string uri
        +string parent_uri
        +string context_type
        +bool is_leaf
        +vector vector
        +sparse_vector sparse_vector
        +string abstract
        +string name
        +string description
        +string created_at
        +int64 active_count
    }
```

### 4.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 主键 |
| `uri` | string | 资源 URI |
| `parent_uri` | string | 父目录 URI |
| `context_type` | string | resource/memory/skill |
| `is_leaf` | bool | 是否叶子节点 |
| `vector` | vector | 密集向量 |
| `sparse_vector` | sparse_vector | 稀疏向量 |
| `abstract` | string | L0 摘要文本 |
| `name` | string | 名称 |
| `description` | string | 描述 |
| `created_at` | string | 创建时间 |
| `active_count` | int64 | 使用次数 |

### 4.3 索引策略

```python
index_meta = {
    "IndexType": "flat_hybrid",  # 混合索引
    "Distance": "cosine",        # 余弦距离
    "Quant": "int8",             # 量化方式
}
```

### 4.4 后端支持

| 后端 | 说明 |
|------|------|
| `local` | 本地持久化 |
| `http` | HTTP 远程服务 |
| `volcengine` | 火山引擎 VikingDB |

## 5. 数据一致性

### 5.1 删除同步

```mermaid
sequenceDiagram
    participant C as Client
    participant VFS as VikingFS
    participant AGFS as AGFS
    participant VB as VectorDB

    C->>VFS: rm("viking://resources/docs", recursive=True)
    VFS->>AGFS: 递归删除内容
    VFS->>VB: 删除 uri 前缀匹配的所有向量
    VB-->>VFS: 确认删除
    AGFS-->>VFS: 确认删除
    VFS-->>C: 完成
```

### 5.2 移动同步

```mermaid
sequenceDiagram
    participant C as Client
    participant VFS as VikingFS
    participant AGFS as AGFS
    participant VB as VectorDB

    C->>VFS: mv("viking://resources/old", "viking://resources/new")
    VFS->>AGFS: 移动内容
    VFS->>VB: 更新 uri 和 parent_uri 字段
    VB-->>VFS: 确认更新
    AGFS-->>VFS: 确认移动
    VFS-->>C: 完成
```

## 7. 存储流程图

### 7.1 添加资源流程

```mermaid
flowchart TB
    subgraph Input["输入"]
        Doc[文档文件]
    end

    subgraph Parse["解析阶段"]
        Doc --> Parser[Parser]
        Parser --> Tree[TreeBuilder]
        Tree --> Temp[临时目录]
    end

    subgraph Store["存储阶段"]
        Temp --> AGFS[AGFS]
        AGFS --> Queue[SemanticQueue]
    end

    subgraph Index["索引阶段"]
        Queue --> Process[语义处理]
        Process --> L0[生成 L0]
        Process --> L1[生成 L1]
        L0 --> VB[向量库]
        L1 --> VB
    end
```

### 7.2 读取流程

```mermaid
flowchart LR
    Query[查询] --> L0[查询 L0 向量]
    L0 --> Candidates[候选集]
    Candidates --> L1[查询 L1]
    L1 --> Score[评分排序]
    Score --> L2[按需加载 L2]
    L2 --> Return[返回结果]
```
